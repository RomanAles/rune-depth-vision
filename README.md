# GPO: RUNE, YOLO и pseudo-LiDAR

Текущая версия: **0.3.0.dev0**, подготовка к 1.0.
Камера по умолчанию — **2**. Статус работ: [ROADMAP.md](ROADMAP.md).

## Быстрый запуск

В корне уже создано Conda-окружение `.venv` с Python 3.11 и CUDA-сборкой PyTorch.
Команды PowerShell не требуют активации:

```powershell
.\.venv\python.exe main.py --mode detect
.\.venv\python.exe main.py --mode depth
.\.venv\python.exe main.py --mode combined
```

Старые команды `app.py` (detect) и `lidar.py` (depth) сохранены.
Выход из графического режима — Q. Для остановки в терминале — Ctrl+C.

## Камера ARDOR GAMING RUNE

Профиль запрашивает 1920x1080, 60 FPS, MJPEG, индекс 2.
В Windows используются DirectShow и запасной MSMF при ошибке открытия или чтения.
Настройки драйвера проверяются по реальному кадру; принятый запрос не гарантирует режим.
FPS драйвера не является измерением FPS нейросети.

Режимы 1920x1080/60 и 2560x1440/30 приведены в
[характеристиках производителя](https://ardor-gaming.com/product/29748686/veb-kamera-ardor-gaming-rune-1920x1080-2560x1440/).
Паспортные 78° не подставляются в горизонтальный FOV: ось измерения не указана.

```powershell
.\.venv\python.exe camera.py
.\.venv\python.exe camera.py --camera 2 --backend msmf
.\.venv\python.exe main.py --mode combined --width 2560 --height 1440 --fps 30
```

Индекс задаётся вручную и может отличаться между бэкендами и после переподключения.
Код не определяет RUNE по имени. Виртуальные камеры тоже занимают индексы.

**Состояние проверки 31.10.2026:** индекс 2 не дал кадр через DirectShow,
а MSMF не открыл устройство. Зависшая диагностика DirectShow была остановлена.
Индекс 2 сохранён по настройке пользователя; работоспособность живого захвата пока не подтверждена.
Нативный вызов драйвера может блокироваться; автоматическое переключение после зависания не реализовано.
Для повторной проверки закройте другие приложения камеры, проверьте разрешения Windows,
подключение USB и индекс устройства.

## Установка окружения

Miniconda на текущем компьютере находится в `D:\miniconda3`.
Окружение проекта — Conda prefix, поэтому `Scripts/Activate.ps1` для него не используется.

```powershell
(& 'D:\miniconda3\python.exe' -m conda shell.powershell hook) | Out-String | Invoke-Expression
conda activate .\.venv
```

Восстановление на другом компьютере с Miniconda:

```powershell
conda create --prefix .\.venv python=3.11 pip --yes
.\.venv\python.exe -m pip install -r requirements-cuda.txt
.\.venv\python.exe -m pip install -r requirements.txt
```

CUDA-файл использует [официальные сборки PyTorch CUDA 12.6](https://pytorch.org/get-started/previous-versions/).
Для CPU пропустите `requirements-cuda.txt`. Версии основных пакетов зафиксированы.
Базовое окружение Miniconda для проекта не изменяется.

В VS Code указан интерпретатор `.venv/python.exe`.
Ядро Jupyter — `Python (GPO RUNE)`; регистрация при восстановлении:

```powershell
.\.venv\python.exe -m ipykernel install --sys-prefix --name gpo-rune --display-name "Python (GPO RUNE)"
.\.venv\python.exe -m jupyterlab
```

YOLO использует `yolo11m.pt` рядом с проектом. Веса моделей, окружение и записи
испытаний не включаются в Git-репозиторий. После клонирования загрузите веса YOLO
из корня проекта:

```powershell
.\.venv\python.exe -c "from ultralytics import YOLO; YOLO('yolo11m.pt')"
```

Модель глубины по умолчанию —
`depth-anything/Depth-Anything-V2-Metric-Outdoor-Small-hf`.
При первом запуске нужен доступ к HuggingFace либо готовый локальный кэш.
`--model` также принимает путь к локальному каталогу модели.
На текущем компьютере проверка глубины использовала существующий пользовательский кэш;
сетевая загрузка весов давала тайм-ауты.

## Конфигурация

```powershell
.\.venv\python.exe main.py --config configs/rune.json
.\.venv\python.exe main.py --config configs/rune.json --mode depth --camera 2
.\.venv\python.exe main.py --help
```

JSON использует имена аргументов с подчёркиванием: `infer_width`, `stop_distance`.
Аргументы CLI имеют приоритет. Неизвестные поля и неверные типы отклоняются.
Пути из JSON считаются относительно самого файла конфигурации; пути CLI — относительно рабочей папки.

| Настройки | Назначение |
| --- | --- |
| `--camera`, `--width`, `--height`, `--fps` | Индекс и запрашиваемый режим захвата |
| `--backend auto/dshow/msmf` | Выбор бэкенда Windows |
| `--fourcc MJPG/YUY2/native` | Запрашиваемый формат драйвера |
| `--autofocus unchanged/on/off` | Изменение автофокуса, если поддерживается |
| `--device auto/cuda/cpu` | Устройство нейросетей |
| `--infer-width`, `--imgsz` | Размеры входа глубины и YOLO |
| `--confidence`, `--weights` | Порог и веса YOLO |
| `--stop-distance`, `--slow-distance` | Пороги предупреждений в метрах |
| `--danger-ratio` | Доля близких достоверных пикселей ROI |
| `--roi X1 Y1 X2 Y2` | Границы ROI в долях кадра |
| `--min-valid-ratio` | Минимальная доля достоверной глубины ROI |
| `--min-component-pixels` | Минимальная площадь связного препятствия |
| `--release-frames` | Подтверждение снятия предупреждения |
| `--max-depth`, `--side-range`, `--stride` | Дальность, ширина и дискретизация карты |

## Алгоритм

Кадр проходит коррекцию дисторсии, если задана калибровка.
В combined обе модели используют один и тот же исправленный кадр.
Глубина интерполируется к его исходному размеру.
Недостоверные значения отображаются чёрным.

ROI проверяется на достаточную долю достоверной глубины.
Препятствие срабатывает по доле близких пикселей либо площади связной области.
STOP и NO_DEPTH применяются сразу; снятие предупреждения подтверждается несколькими кадрами.
При неизвестной глубине состояние CLEAR не выставляется.
Расстояния являются оценками осевой глубины Z, а не измерениями дальномера.

Pseudo-LiDAR использует `X=(u-cx)*Z/fx`, `Y=(v-cy)*Z/fy`.
При известной высоте камеры применяется фильтр по высоте над полом,
а наклон учитывается при проекции на горизонтальную плоскость.
Без высоты камеры остаётся прежний приблизительный фильтр относительно камеры.

Расстояние до объекта — медиана достоверной глубины внутренней части рамки YOLO.
Это эвристика: фон внутри рамки может влиять на оценку.

## Калибровка

`--calibration camera-calibration.json` загружает поля:
`width`, `height`, `fx`, `fy`, `cx`, `cy`, `distortion`.
Первые два поля — исходное разрешение калибровки.
Коэффициенты дисторсии записываются в порядке OpenCV.
Пример структуры (числа **демонстрационные**, не калибровка RUNE):

```json
{
  "width": 1920,
  "height": 1080,
  "fx": 1400.0,
  "fy": 1400.0,
  "cx": 960.0,
  "cy": 540.0,
  "distortion": [0, 0, 0, 0, 0]
}
```

При пропорциональном изменении разрешения параметры масштабируются.
Другое соотношение сторон отклоняется: оно может означать другой кроп камеры.
Без калибровки используются `--fx/--fy/--cx/--cy` либо приближение `--fov-deg 70`.

Для фильтрации относительно пола укажите **измеренную** высоту камеры в метрах
и наклон вниз в градусах, например `--camera-height 1.0 --pitch-deg 15`.
Это тоже пример, а не сохранённые параметры установки.
`--min-height` и `--max-height` задают рабочую полосу высот над полом.
Изменение автофокуса, цифрового кропа и установки камеры требует проверки калибровки.

## Видео, запись и диагностика

```powershell
.\.venv\python.exe main.py --mode combined --source input.avi --headless --max-frames 300
.\.venv\python.exe main.py --mode combined --output-dir results --save-depth
```

В `output-dir` создаётся отдельный каталог запуска с файлами:

- `rgb.avi`, `depth.avi`, `bev.avi` — доступные виды (в detect только RGB).
- `events.jsonl` — кадр, время UTC, сырой и сглаженный статус, объекты, глубина и тайминги.
- `settings.json` — параметры запуска.
- `summary.json` — число кадров, длительность и p50/p95 по этапам.
- `depth-XXXXXX.npy` — сырая глубина при `--save-depth`.

`--output-fps` задаёт частоту воспроизведения сохранённого видео; это не FPS обработки.
При `--headless` без записи отрисовка пропускается.
Процентили считаются по последним 4096 кадрам, чтобы история не росла без ограничений.
Тайминг total включает обработку и программное чтение кадра, но не задержку USB/буфера камеры,
загрузку моделей или запись самой строки JSONL.

Проверка 31.10.2026: RTX 4070 SUPER, combined, синтетическое видео 640x360,
60 кадров, infer-width 518, без окон и записи:
медиана total 30.85 мс, p95 41.65 мс. Это технический замер, не приёмка Full HD или точности.

## Проверки и точность

```powershell
.\.venv\python.exe -B -m unittest discover -s tests -v
.\.venv\python.exe -m pip check
.\.venv\python.exe evaluate.py measurements.csv --output reports/depth-errors.json
```

Контрольный CSV должен содержать `true_m,estimated_m` с положительными расстояниями.
`evaluate.py` считает MAE, RMSE, смещение, среднюю относительную ошибку и p95 абсолютной ошибки.
Порядок реальных испытаний: [docs/TESTING.md](docs/TESTING.md).

## Ограничения

Метрическая глубина по одному RGB-кадру требует проверки на реальных сценах.
Текущая Outdoor-модель обучена для уличных сцен
([карточка модели](https://huggingface.co/depth-anything/Depth-Anything-V2-Metric-Outdoor-Small-hf));
для помещения следует отдельно проверить подходящую модель.
Погрешность расстояний, ложные тревоги, пропуски, часовой тест и живой захват камеры 2
пока не прошли приёмку. Версия 1.0 ещё не выпущена.
